# S3 Interview Questions

## S3 Basics

1. **What is Amazon S3?** *Answer:* Amazon S3 (Simple Storage Service) is an object storage service offering industry-leading scalability, data availability, security, and performance. It stores data as objects within buckets. S3 provides 11 nines (99.999999999%) of durability by storing data across multiple AZs.

2. **What is an S3 bucket?** *Answer:* A bucket is a container for objects (files) stored in S3. Bucket names must be globally unique across all AWS accounts. Buckets are created in a specific region and can store an unlimited number of objects.

3. **What is an S3 object?** *Answer:* An object is a file and any metadata that describes the file. An object has a key (the file name/path), value (the actual data), version ID (if versioning is enabled), and metadata (key-value pairs). Maximum object size is 5 TB; objects larger than 100 MB should use Multipart Upload.

4. **What are S3 storage classes?** *Answer:*
   - **S3 Standard:** High durability, availability, and performance for frequently accessed data.
   - **S3 Standard-IA (Infrequent Access):** Lower cost, retrieval fee. For data accessed monthly.
   - **S3 One Zone-IA:** Stored in single AZ. Lower cost, suitable for non-critical, reproducible data.
   - **S3 Glacier Instant Retrieval:** Archive storage with millisecond retrieval. For quarterly access.
   - **S3 Glacier Flexible Retrieval:** Archive with retrieval in minutes to hours. For annual access.
   - **S3 Glacier Deep Archive:** Lowest cost. Retrieval in 12 hours. For 7-10 year regulatory archiving.
   - **S3 Intelligent-Tiering:** Automatically moves objects between tiers based on access patterns.

5. **What is S3 versioning?** *Answer:* Versioning allows you to keep multiple variants of an object in the same bucket. It protects against accidental deletes or overwrites. Once enabled, it cannot be disabled (only suspended). Each version has a unique version ID. Deleting a versioned object adds a delete marker instead of permanently removing it.

## Security

6. **How do you control access to S3?** *Answer:* Multiple mechanisms:
   - **Bucket Policies:** JSON-based resource policies attached to the bucket. Apply to all objects in the bucket. Good for cross-account access or making a bucket public.
   - **IAM Policies:** Attached to users/roles. Control what S3 actions that identity can perform.
   - **ACLs (Access Control Lists):** Legacy, object-level access control. AWS recommends disabling ACLs and using bucket policies instead.
   - **S3 Block Public Access:** Account/bucket level setting to prevent any public access, overriding bucket policies.

7. **What is S3 Bucket Policy vs IAM Policy?** *Answer:*
   - **Bucket Policy** is attached to the bucket (resource-based). Can grant cross-account access without creating IAM roles.
   - **IAM Policy** is attached to users, groups, or roles. Controls what that identity can do across all S3 resources.
   - If both exist, the most permissive combination applies — unless there's an explicit Deny, which always wins.

8. **What is S3 Server-Side Encryption (SSE)?** *Answer:* SSE automatically encrypts data at rest:
   - **SSE-S3:** AWS manages keys using AES-256. Simplest option.
   - **SSE-KMS:** AWS KMS manages keys. Provides audit trail via CloudTrail and key rotation control.
   - **SSE-C:** You provide and manage your own encryption keys. AWS does the encryption but never stores your key.
   - **Client-Side Encryption:** You encrypt data before sending to S3. AWS never sees unencrypted data.

9. **What is S3 Pre-Signed URL?** *Answer:* A pre-signed URL grants temporary access to a private S3 object without requiring AWS credentials. Generated by an AWS identity with permissions to the object, it includes an expiration time (up to 7 days for SDK-generated URLs). Useful for allowing users to download or upload specific files without making the bucket public.

10. **What is S3 Block Public Access?** *Answer:* A set of four settings at the account or bucket level that prevent S3 objects from being made publicly accessible, even if a bucket policy or ACL allows it. It overrides bucket policies — enabling this is a best practice for buckets that should never be public.

## Performance & Features

11. **What is S3 Transfer Acceleration?** *Answer:* Transfer Acceleration uses CloudFront's globally distributed edge locations to speed up uploads to S3 from distant locations. Data is routed to the nearest edge location and then transferred over AWS's optimized network backbone to S3. Best for large files uploaded globally.

12. **What is Multipart Upload?** *Answer:* Multipart Upload allows you to upload a single object as a set of parts (in parallel). Recommended for objects larger than 100 MB, required for objects over 5 GB. Benefits: improved throughput through parallelism, ability to pause and resume uploads, and ability to re-upload only failed parts.

13. **What is S3 Select?** *Answer:* S3 Select allows you to use SQL expressions to retrieve only a subset of data from an object (CSV, JSON, Parquet). Instead of downloading the full object and filtering client-side, S3 filters server-side, reducing data transfer by up to 400x and improving query performance.

14. **What is S3 Lifecycle Policy?** *Answer:* Lifecycle policies automate the transition of objects between storage classes or their expiration. Example: transition objects to S3-IA after 30 days, to Glacier after 90 days, and delete after 365 days. Helps reduce costs without manual intervention.

15. **What is S3 Event Notification?** *Answer:* S3 can send notifications when specific events occur in a bucket (e.g., object created, deleted, restored). Notifications can be sent to SNS topics, SQS queues, or Lambda functions. Used to trigger workflows when files are uploaded.

## Advanced Concepts

16. **What is S3 Replication?** *Answer:* S3 replication automatically copies objects to another bucket:
    - **Cross-Region Replication (CRR):** Replicates to a bucket in a different AWS region. Used for disaster recovery and geographic compliance.
    - **Same-Region Replication (SRR):** Replicates to a bucket in the same region. Used for log aggregation or live replication between production and test accounts.
    - Requires versioning to be enabled on both source and destination buckets.

17. **What is S3 Object Lock?** *Answer:* Object Lock prevents objects from being deleted or overwritten for a fixed retention period or indefinitely. Useful for compliance with regulations requiring Write Once Read Many (WORM) storage. Two retention modes:
    - **Compliance:** No one, including root user, can delete or modify the object until retention period expires.
    - **Governance:** Users with specific IAM permissions can bypass the retention.

18. **What is S3 Requester Pays?** *Answer:* Normally, the bucket owner pays for storage and data transfer. With Requester Pays enabled, the requester (person downloading data) pays for data transfer costs. Useful when sharing large public datasets where you don't want to pay all download costs.

19. **How does S3 achieve high durability?** *Answer:* S3 Standard stores data across a minimum of 3 AZs within a region. It uses redundancy at the hardware level and automatically repairs data using checksums. The 11 nines (99.999999999%) durability means if you store 10 million objects, you might expect to lose one object every 10,000 years.

20. **What is S3 Access Points?** *Answer:* S3 Access Points are named network endpoints attached to a bucket, each with its own access policy. They simplify managing access for shared datasets. Instead of one complex bucket policy, you create separate access points with specific policies for each application or team (e.g., one read-only access point for analytics, one read-write for the app).
